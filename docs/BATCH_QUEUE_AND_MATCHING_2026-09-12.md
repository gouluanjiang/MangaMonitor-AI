# 批量下载队列、历史整理与跨来源关联

用户已验收 Pica 同源跳转修复，并要求继续下一阶段。本批沿用已验收的 JM/Pica 单本下载、图片处理、最终目录格式与电脑登记流程，将用户明确确认的多本作品按顺序调度。

## 交付行为

- 收藏、搜索或关注列表的多选栏可准备下载；队列也支持每行一个编号或受支持链接，每批最多 50 项。来源详情的单本入口保留。
- 准备阶段顺序读取作品信息并列出真实标题、来源编号、保存位置。重复编号和读取失败分别显示，不会在准备阶段开始图片下载。确认后将全部有效计划一次加入队列。
- 同一时间处理一本作品，保留每本内部的 20 图片生命周期窗口。可在下载时追加任务；正常图片进度更新不会让新的确认单过期。
- 等待任务保持“等待下载”；单本暂停或失败后继续处理后续已确认作品。支持暂停整队，以及按来源继续最多 50 本暂停任务。已进入最终保存的当前作品可能完成保存，后续作品保持暂停。
- 应用重启恢复记录，但不会自动联网下载；用户显式继续后绑定当前账号会话。已失效的账号、任务、目录授权不会被下一本继承。
- 队列支持标题/编号搜索、来源筛选和完成历史。可移除指定或当前筛选下最多 50 条完成记录，电脑漫画、电脑索引与手机名单均保留。可见任务上限从 50 调整到 500；保留紧凑来源身份记录用于重新关联/重复目标核对，不保存额外漫画副本。
- 来源详情提供 JM↔Pica 人工关联：输入另一来源编号、读取其详情、核对两边标题及版本，再明确确认。每本最多一对，可解除。标题相近、甚至标题相同都不会自动产生关联。
- 已确认关联用于双库状态显示：手机存在优先“已入库”，否则有电脑副本为“已下载”。手机标记、TXT 名单和电脑来源编号各自保存，不因关联被改写。若另一来源已下载，确认单提示已有副本，是否再下载由用户确认。

## 下载契约与上游复核

本批按 `AGENTS.md` 重新阅读 thaw gate、桌面下载 gate、目录兼容与 upstream reference，并重新打开以下固定源码：

- lanyeeee/jmcomic-downloader `f0cdd724af6892002f2fb7be883b88832cebe7e9` 的章节/图片下载实现；
- lanyeeee/picacomic-downloader `77c8b62ede42b3afc074506d092313816af8092d` 的下载管理器；
- hect0x7/JMComic-Crawler-Python `9fddb0494caf0cdc812ac6cbfc1c62f4f845b058` 的下载器及整体成功判定。

复用有界调度、等待全部图片任务和完整作品完成的思路。上游的覆盖、按存在跳过、删除目标与宽松完成条件不作为本项目权限。MIT 声明与固定协议不变。本批新增跨作品调度，不变更图片传输、域名、重试或图片格式策略。

每个准备计划独立保存在 native 内存；确认在当前锁内重查来源、目录身份与重复项，再原子保存队列。任务批准与进度 revision 分离；排队资格只在本次进程内存在。worker 直到图片处理退出、完整保存及电脑登记结束后才取下一本。账号凭据只存 native 会话内存。真实媒体执行继续拒绝 GitHub Actions。

整理历史只更新私有任务记录；必要身份证据独立保留，以免整理后遗忘曾被手动重新关联的本地作品。跨来源人工关联存入单独的固定私有文档，有一对一校验和 revision 冲突检查。

## 验证安排与验收

正式测试、跨平台构建、Clippy、浏览器交互与 Windows WebView/重启检查全部在既有 CI 执行。本地仅编辑、格式化、独立代码审查和交付工件核验，不在两边重复跑同一套验证。准确提交、各套测试数量、CI 链接与 Dev SHA256 记录在最终交付报告和草稿 PR #19。

新增合成回归覆盖批量确认/取消、下载中追加、去重、暂停等待任务、失效会话/目录、重启不自动执行、历史整理保持文件/双库状态、人工关联确认/冲突/解除与页面恢复。旧来源协议、完整性、JPG/Pica 图片处理及文件删除后重下继续由已有测试覆盖。

真实验收由用户自行选择作品，建议先用 2–3 本：

1. 收藏多选或粘贴多个编号，检查标题、目录和重复项；先取消一次，确认队列未新增，再确认下载。
2. 下载第一本时追加一本，观察依次执行；暂停整队、按来源继续，完成后核对文件和电脑状态。重启后未完成任务应暂停。
3. 完成历史中搜索并移除一条记录，确认漫画文件、电脑库及手机标记仍在。
4. 选择确认为同作品的 JM/Pica 两个版本，关联后检查状态一致；解除后回到各来源原有证据。
