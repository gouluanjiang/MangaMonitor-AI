# 1.0.1 后浏览与下载体验改进（已确认范围）

确认日期：2026-09-29。当前阶段：用户已验收通过原批次大部分功能，并提出下述五项定向修补；新修补仍需工程检查与用户验收。工程检查及候选交付记录见 [PR #23](https://github.com/gouluanjiang/MangaMonitor-AI/pull/23)，正式发行尚未完成。已安装和已发布的 1.0.1 保持原样。用户已明确取消单本和批量下载的第二次确认；点击下载本身授权该次下载，既有文件身份、来源、目录校验与禁止覆盖边界继续有效。

## 本轮验收反馈修补

- 多选移入主滚动区之外、状态栏上方的实色操作带。工具占实际布局空间，滚动到中途也能操作；隐藏页面不保留可见操作带。
- 右键菜单标题完整换行，长连续文本可断行，极长标题在视窗内滚动查看，不再截去后半段。
- BL 过滤补入哔咔明确分类 `耽美花園` / `耽美花园`；增加明确 AI 标签，包括完整 `AI`、`AI作画`、`AI绘图`、`AI生成`、`AI Art`、`AIイラスト` 等规范化写法。只认明确标签或分类，不在标题、作者名里猜测，未知不增加逐本请求。
- AI 与 BL 的证据同步保留到目录精简缓存和本地元数据读取，沿用全页面内容过滤；不删除漫画、下载记录或网站收藏。
- 失败的在线或本地封面可直接单击重试；多选时仍只勾选，失败封面的连续双击不会意外打开阅读器。在线显式重试会重新读取该本封面资料，避免复用已失效的旧地址；正常封面加载不增加详情请求。

新增验收要求：窄窗和宽窗操作带都不遮封面；菜单全文可读且不出屏；新标签在分类、标签和缓存路径均生效；失败封面鼠标与键盘重试、单本缓存失效、会话隔离、阅读器与多选手势互不冲突。之前已被旧版本丢弃的标签无法凭空恢复，随正常来源刷新补充；不启动全作者扫描。

字体、全局按钮与整体 UI 风格仍由用户在本批完成后讨论，不包含在本轮改动中。

## 已实现范围

1. 单本、批量下载直接加入队列，留在当前页面。连续点击不能因忙碌而丢失；显示正在加入、已排队、下载中或重试下载。
2. 已失败作品再次下载应重试原任务、复用有效进度；批量中的单项失败不阻断其他项目，不重复创建已有任务。
3. 所有支持批量下载的浏览列表提供底部实色操作带内的常驻多选入口，进入后显示已选数量、下载和取消，占用实际布局空间；只清除成功提交的选择。
4. 所有漫画浏览页面（漫画库、收藏、作者更新、各类搜索、最近更新、排行榜、已下载列表等）在本次运行期间保存位置与相应浏览条件；重启从顶部开始。页面和来源独立，使用漫画标识与偏移恢复，内容变化时使用邻近项；不改变阅读器原有阅读进度。
5. 最近更新按来源＋作品编号排除作者更新历史已确认归属作品；其他关键词结果不参与，不恢复跨站自动同作推断。
6. 仅下载异常触发短暂提示，同一批连续失败聚合，旧失败不重复通知，成功不通知；具体错误在队列保留。
7. 正常封面单击仅突出卡片，失败封面单击重试；双击小窗阅读，右键鼠标位置菜单提供详情／程序内阅读／小窗阅读；标题单击详情；多选时单击勾选且双击不打开阅读。
8. 卡片作者名可点击并默认搜索 JM＋哔咔，多个作者独立；最多两行，悬停展示完整署名。
9. 合并为单一搜索入口，作者／关键词／编号或链接／标签模式。作者自动读完整范围；关键词与标签先首批后按浏览续读，分别标明来源总数、已读取范围与库存统计。
10. 全局按明确 BL、AI 标签、分类及同义／写法变体过滤；不靠标题、作者、封面猜，不误判无关子串；未知照常显示，不为过滤额外逐本请求，不删本地或网站数据。保留过滤依据，不能因缓存压缩丢失。
11. 点击标签搜索当前作品所在来源，使用标签语义；无法证明标签或完整性时明确范围，不把关键词命中冒充标签命中。

## 来源查询与过滤实现记录

以下实现已进入本批工作区；此处记录代码与静态复查结论，不代表 CI、真实来源核验或用户验收已通过。

| 查询 | 原生接口 | 边界 |
| --- | --- | --- |
| JM 标签 | `GET /search?main_tag=3&search_query=...&page=...&o=mr` | 与普通关键词的 `main_tag=0` 区分；标签结果不能回退到编号详情 |
| 哔咔标签 | `GET comics?t=...&s=dd&page=...` | 使用 `t` 字段，不使用关键词搜索代替 |
| 哔咔分类 | `GET comics?c=...&s=dd&page=...` | 使用 `c` 字段；`SourceWork.categories` 保留分类来源，不能把分类误当普通标签 |

接口根据项目已有固定上游版本核对：JM 的 [search_tag 定义](https://github.com/hect0x7/JMComic-Crawler-Python/blob/9fddb0494caf0cdc812ac6cbfc1c62f4f845b058/src/jmcomic/jm_client_interface.py) 与 [移动端 search 实现](https://github.com/hect0x7/JMComic-Crawler-Python/blob/9fddb0494caf0cdc812ac6cbfc1c62f4f845b058/src/jmcomic/jm_client_impl.py)；哔咔的 [PicaComic-go Comics 方法](https://github.com/Miuzarte/PicaComic-go/blob/25d20c875b69c94f7980fad8d8d5b06c7ef3d1cb/PicaComic.go)。只采用接口与字段事实，没有复制其下载或重试实现，也未发送真实账号查询。

`source_query` 新增 `tag/category`；分类请求限定哔咔。会话、页码、查询长度、控制字符与不可反转边界继续在原账户服务中校验。`readCompleteSearch` 的 `requestKind` 区分查询类型，`pageLimit: 1` 允许按需续页；合法暂停不宣称完整，重复页、来源总数变化、短尾页、无进展等原有完整性检查继续有效。作者检索仍使用原完整查询逻辑。

BL 过滤只认元数据中的完整明确标签，如 `BL`、`耽美`、`Yaoi`、`Boys Love` 及实现中列明的等价写法。前后端统一执行 Unicode NFKC、大小写、空白及撇号规范化；不会因标题、作者名、`black`、`非BL`、`GL` 等无关内容而命中。没有标签证据的作品正常展示。运行期索引仅以来源＋作品编号保留已明确的 BL 依据，使另一页面暂缺标签时仍能沿用；它不进行跨站同作猜测，不增加元数据请求。

哔咔每个原始 `tags/categories` 数组仍最多 64 项，每项仍最多 2,000 UTF-16 单位；合并标签上限为 128。单作品真实 JSON 的 **64 KiB 上限不变**。分类补充导致超限时，先让可选描述或无关标签让位；保留明确 BL 与语言冲突所需证据；无法容纳时保持未知或回到原本有效元数据，不能让可选分类挡住原可读作品。浏览缓存只保留最多两种语言＋一个 BL 标签及对应的必要分类来源，并继续受 32 MiB 预算约束。

旧 DTO 不带 `categories` 时仍可读取；旧作者目录、下载记录不需要重写或迁移。**以前版本已经丢弃的 BL 分类无法从空缓存还原**，这部分仍按未知处理，随正常刷新或详情读取补充，不强制重扫全部作者。下载任务视图的 `tags/rootId` 直接来自现有已保存任务元数据与目录身份，不改任务、漫画文件或下载历史。

两份 Cargo.lock 均仅给 `workbench-sources` 接入仓库已锁定的 `unicode-normalization 0.1.25`，未新增依赖版本。静态复查已核对原生路由区分、锁文件对应、序列化上限、缓存继承与未知分类边界；已增加路由编码、分页续读、分类来源、BL 正反例、64 KiB 边界、账户隔离及下载 DTO 的合成用例。正式运行结果由本批 CI 与后续验收记录补充。

## 必须验收

- 下载免确认、连续点击、重复点击、失败重试、批量部分失败、阅读器下载入口都一致，不跳页面。
- 异常通知合并、自动消失、旧失败不重复，正常下载无通知。
- 在每个漫画浏览入口滚动后切换页面／来源并返回，恢复到正在看的作品附近；过滤或入库改变前方条目后也稳定。
- 过滤导致整页无可见作品不代表来源结束，后续分页仍能继续；续页后不跳到底部、不连续无限抓取。
- 多选浮动入口和操作条不遮挡内容；鼠标及键盘可用，三种封面操作无冲突。
- 作者／标签点击、搜索切换、双站范围、分页统计、BL过滤、更新去重保持一致；原有入库记录和下载历史正确。
- 正式检查与构建只在 CI；本地仅独立诊断和实际界面验收。工程通过、真实核验、用户验收、正式发行分开记录。

## 回归与交付边界

工程回归覆盖直接下载、连续提交、原任务重试、批量部分失败、异常提示、封面三种操作、全页面位置、缓存来源切换、筛选后的邻近作品恢复、空可见页续读、双站作者查询、原生标签路由与明确 BL 过滤。核验使用合成账户、目录和作品；没有以本批检查为由下载真实漫画或重新扫描全部关注作者。

回归期间修正了缓存目录短暂为空时遗漏位置恢复、来源切换清掉原筛选条件、同一搜索模式返回仍停在详情、倒序目录完成后恢复到尾部，以及延迟滚动事件关闭新菜单的问题。窄窗口的多选操作栏跟随侧栏宽度；菜单新增错误提示后重新保持在窗口内；作者文字链接避免沿用旧详情按钮样式。

CI 的合成浏览器、后端及 Windows 隔离安装结果不能代替网站实机结果或用户验收。候选程序、实际代码修订与最终检查链接由 PR 交付记录明确列出；使用本批候选验收后再决定合并或正式发布，不能把现有 1.0.1 的验收沿用到这些新交互。
