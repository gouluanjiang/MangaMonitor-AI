# 下载完成后入库被目录重读阻断的修复

## 已确认的问题

用户重新下载后，图片已全部取得，但任务停在 `LIBRARY_BUSY`，没有生成最终 ZIP，也没有登记漫画库。这与前一项 Pica 图片格式兼容问题不同：完整暂存清单及图片哈希有效，失败发生在保存／入库阶段。

目录每次重新读取都会递增索引代次。旧下载任务把该代次与来源、目标目录、授权和暂存凭据绑定；原实现即使目录读取已结束，仍要求重试时与最初代次完全相同，因此同一个目录的正常重读也会使任务无法继续。不能通过直接修改私人任务的绑定来恢复。

## 修复范围和边界

- 用户明确点击重试／继续时，校验当前目录 ID、路径与实际文件身份均与原任务一致，且新的目录读取已完成，才为本次运行记录当前索引代次。
- 原下载任务的代次、授权、目标哈希、来源编号和暂存／输出凭据不变。当前索引代次只保留在本次进程的运行许可中，供最终登记使用；重新打开程序不会自动运行任务。
- 运行中再次重读目录仍会阻止旧运行继续写入。更换目录、目录实体被替换、读取暂停／未完成、过期控制和伪造登记凭据仍拒绝。
- 已有完整暂存清单时，校验并复用图片完成 ZIP 与入库；ZIP 已完成但登记失败时，校验并复用原 ZIP，不覆盖其他文件。
- 队列明确提示“图片已下载齐，保存或入库尚未完成”，并把 `LIBRARY_BUSY` 提示改为完成目录读取后重试当前操作。

已按 `DOWNLOAD_EXECUTOR_THAW_GATE.md` 复核桌面保存、登记、重试及其凭据契约。本次不更改来源协议、图片处理、并发或请求策略，复用现有固定上游审查。生产关闭、来源所有权规则、版本与发布状态保持原约束。

## 验证计划和真实操作

新增离线回归覆盖同目录重读后的目录／ZIP 保存、保存后登记前重读、再次重读与重启使运行许可失效、批量继续、不同目录与文件身份拒绝，以及 Pica 混合图片格式完整进度的 ZIP 入库。新增前端场景验证完整图片进度仍属于“需要处理”，重试登记后才变成“已下载”。正式测试和构建仅在 CI 进行，本机不重复运行。

按用户明确要求，旧失败任务已在程序关闭、锁定私人存储后定点移除，其 57 个旧暂存图片也已删除。删除前核对精确路径、文件身份、全部文件大小和哈希；其他 3 条记录、新任务 326 个暂存图片及漫画库索引均保持不变。详细回执、队列 JSON 备份与真实编号只保存在 Git 外，没有删除漫画库作品。
