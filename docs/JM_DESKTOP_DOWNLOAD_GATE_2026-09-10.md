## 桌面手动任务与已有核心的关系

桌面私有任务明确记录 `origin=manual`，由用户确认所见作品和最终目录产生授权，绑定 task/revision/target/root identity/layout。只投影实际当前任务和批准到 A6 `State.pending` / `GateLedger`，复用 `execute_live` 的当前代次、预检、媒体描述、隔离暂存、哈希清单和收据验证。

这不是云端作者范围的 `PROVEN_NEW` 证据。不得合成 matcher 结论或调用 V1.5–V1.8 的生产库存/任务完成链来伪造符合该条件。既有入口和 production-disabled 状态保持。实际网络执行在 GitHub Actions 中拒绝；合成测试只使用注入的测试传输和临时目录。

本批新增的是明确的桌面手动新增目录物化层：批准绑定选择器目录身份、最终新目录名及布局版本；暂存完整后再绑定 exact manifest 与布局映射；立即重新检查任务/会话/目录身份，然后只向本任务拥有的新目录写入。不得覆盖既有作品或替换目录。元数据、封面和图片布局构成独立的最终清单；整个树复核后才可交给电脑库登记。新目录先写入持久布局标记，普通扫描在最终清单齐备前不发布该目录的已下载记录。暂存完成不能称为已下载。

## 交互与持久化契约

- `jm_download_prepare({scope:{source:'JM',sessionId},input,rootId,generation})`：只预备计划；编号/受支持链接解析在 native，renderer 不传物理路径、媒体 URL 或凭据。
- `jm_download_confirm({planId,expectedRevision})`：确认仍然当前的计划，持久化并启动一本任务。
- `jm_download_read({})`：只读恢复。应用重开后未完成任务暂停，不能自动开始联网或写漫画文件。
- `jm_download_control({scope,taskId,expectedRevision,action})`：显式暂停、继续或重试。控制 revision 与图片进度分开，旧代次不能再次写入。
- 单本单 worker。暂停在当前在途请求结束后的下一授权点生效；保留可验证的已有结果。重试不能将残缺作品误报完整，也不能因登记失败重新下载完整漫画。

任务响应仅含作品、显示目录、状态、数量与安全错误码。计划和运行账号会话只存内存，无密码/token 入队列。读坏私有文档不能回退成空队列后覆盖原文档。

输出采用既有下载器目录约定：作品目录、`元数据.json`、封面、章节目录、`章节元数据.json`、四位页码图像。已完整物化后只扫描这一目录，匹配来源编号和页数，电脑索引保存成功才报告 `downloaded`。不改变手机名单、不全库扫描、不删本地副本。

## 验收与分工

核心负责私有任务、A6 适配、低并发执行、暂停/续接、最终目录与证明；native 负责主窗口 IPC、账号会话、选择器目录代次和定向登记；UI 负责具体确认、真实队列和移除 native 模拟进度；独立检查负责定向登记和边界回归。

正式编译与测试只在 CI。覆盖：取消无任务；失效计划/会话/目录拒绝；暂停/重开不自动执行；失败不完成；已验证文件复用；既有目标不覆盖；部分/错误 ID/错误页数不能登记；手机状态不改；真实任务没有模拟计时器。CI 通过与真实验收分开记录，未完成项目不能标成通过。

## 本批临时数据生命周期补充（2026-09-11）

用户要求保留电脑作品，并关注不必要的本机存储负担。桌面下载在最终作品完整复核、PC索引成功登记且任务完成持久化之后，可释放本任务自行创建的私有暂存副本。清理只针对已验证manifest中的对应临时文件及已空目录；未知文件、身份变化或路径重定向均保留。暂停、失败的任务保留续接数据。此能力不接收renderer路径，不触及最终作品、原有漫画、手机库或其他任务，也不改变旧A6收据的production/replacement/physical-delete flags。它是用户在桌面确认的单本下载中程序临时数据的生命周期，不能被复用于生产库删除。此处仅记录开发范围，真实样本仍待CI后的具体目录与执行确认。
