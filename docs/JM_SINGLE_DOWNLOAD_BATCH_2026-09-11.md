# JM 单本下载开发批次

本批从双库索引进入实际下载：在 JM 作品详情或下载队列输入编号/受支持链接，核对作品和电脑目录后，单独确认一本任务。Pica 下载安排在下一批。版本暂沿用 0.3.4，不生成新安装包，不接入应用内更新。

## 已实现的行为

- 原生程序使用真实下载队列；浏览器 UI 样例继续独立。原生界面不再使用模拟计时器、模拟离线/退出或假的下载进度。
- 一次处理一本，展示实际图片数量和状态；未知总数时不估算进度或剩余时间。
- 暂停、继续和显式重试；重新打开程序只恢复任务记录，未完成任务等待用户点击继续。
- 复用已有 JM 章节、图片枚举、固定来源请求、GIF/WebP 处理和完整下载校验。写入前保存该页的预期大小/哈希，解决图片刚写完而进度尚未保存时的恢复问题。
- 作品目录包括 `元数据.json`、`cover.jpg`、章节目录、`章节元数据.json` 及四位页码图片。JM 元数据字段与 pinned 上游结构对齐；未知统计字段用兼容默认值，并明确标记来源。
- 完成目录的图片、元数据和清单核对后，仅登记这一部电脑作品。失败或尚未完成的本程序目录不会被普通扫描误报已下载。
- 电脑已有同来源作品或同名目标时拒绝覆盖。已验证完成的结果可用于重试登记，不重复下载整本。
- 最终目录和电脑索引均完成且任务已持久化后，精确释放本任务的临时副本；暂停和失败的续接数据保留，最终电脑作品保留。
- 手机名单不随下载变化：手机存在依然优先“已入库”；仅电脑存在为“已下载”。

## 本批范围限制

本批下载输出保留还原后的 WEBP/GIF，不新增全书格式转换或 PDF/CBZ 导出。`cover.jpg` 使用第一张已验证页面生成缩略图；章节没有通过当前核心取得原始标题时，使用章节编号。布局兼容不等于完整复制上游下载器全部展示字段或导出功能。

来源浏览封面仍仅在应用会话中缓存。完整下载目录的 `cover.jpg` 属于作品文件，随电脑漫画保留。输出还包含本程序的布局/完成清单，用来阻止半成品误入电脑索引。

当前为单本流程，任务记录上限 50，每本最多 9999 页。历史任务整理和批量调度留给后续队列批次。当前任务绑定用户确认时的电脑目录与代次；目录重新选择/重新读取造成绑定变化时停止执行，避免向过期目录继续写入。

## 验证记录规则

正式格式检查、编译、Rust/Node/Chromium 回归和实际 Windows WebView 检查均由 CI 执行。本机只做代码编辑、格式编辑和独立只读审查，不重复执行 CI 套件。精确通过状态以 PR #19 对应提交的检查及本批交付报告为准。

新增覆盖包含：空队列只读、取消/失效计划、主窗口 IPC 权限、会话失效、暂停与旧任务交接、重启恢复、图片写入与进度的交接、完整清单、残缺文件续接、已有目标保护、定向登记、手机状态保留及临时副本生命周期。所有公开测试使用合成作品和临时目录。

真实下载验收与合成 CI 分开。用户已提供一个私有 JM 样本；在具体目录和范围明确后验收，不把合成测试称为真实下载成功。CI 会上传经过构建和 WebView 检查的 EXE，供本批手动验收使用；它不是安装包或正式版本发布。
