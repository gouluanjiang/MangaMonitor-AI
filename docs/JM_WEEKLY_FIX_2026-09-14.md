# JM 周榜修复与入库统计说明

2026-09-14，接续已交付的 `6f794fd` Dev 版本，处理用户本轮验收反馈。

## 已定位的问题

JM 周榜打不开是项目的解析问题。读取公开的 `/week` 返回了 256 个期数，其中 174 个 `title` 为空，包括当前期数；日期与期数文字保存在 `time`。原代码要求所有标题非空，因而一条空标题就阻止整个期数列表读取。

已固定版本的 JM 下载器 `WeeklyPane.vue` 本来就用 `category.time` 显示期数。采用这一字段不需要修改接口、账号、域名或漫画解析规则。

另一个体验问题是默认选择了第一个类型“韓漫”。诊断时它确实返回 0 条，来源另一个“日漫”类型则返回 20 条且总数为 20。空类型不是网络错误。

## 修复内容

- 期数标题可为空，使用日期文字；日期和标题都为空时显示明确的期数 ID，不丢掉对应榜单。标识、重复项、数据类型和文本长度继续校验。
- JM 默认选择来源提供的“日漫”类型；仍可切换所有原有类型和期数，Pica 默认周榜不变。
- 首次失败不再误称“已读取榜单保留”；有当前结果时仍保留它们。正常空榜单提示切换期数或类型。
- 收藏、搜索、作者更新和榜单统计旁统一说明：按本软件对应来源的下载记录和实际文件统计；未登记的旧漫画可能显示“未入库”。不改变状态判断。

## 旧漫画的后续安排

用户已再次确认不恢复自动匹配。旧漫画即使存在于磁盘，缺少相应来源的有效下载登记时仍不计入线上“已入库”。santa 的 0 部与这个口径一致，不代表磁盘上不存在其作品。本轮未检查用户的具体文件，也不声称完成了该作者的私人库核对。

现有旧漫画的人机辅助核对改为 **V1 完成后处理**，届时确定核对方式及独立登记依据。当前不实施、不把旧文件伪造成软件下载记录，不恢复自动或跨站匹配。

## 验证边界

- 真实来源诊断：2026-09-14 16:59–17:01（本机时间），总共四次匿名公开文字 GET；两次期数列表、两个类型各一次。返回结构确认了空标题原因及非空榜单字段。没有账号访问、图片下载、私人库扫描或数据修改。
- 工程回归：添加空期数标题、日期及 ID 回退的来源测试；非法类型、超长值仍被拒绝。现有界面回归增加日漫默认值、日期标签、正常空榜单及首次失败不误报保留的检查。
