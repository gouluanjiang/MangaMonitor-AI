日期：2026-09-09。项目：MangaMonitor-AI。开发分支：`codex/local-workbench-preview`。沿用[草稿 PR #19](https://github.com/gouluanjiang/MangaMonitor-AI/pull/19)。

本批桌面基础、本地设置和书单管理已完成实现及本批验收，Windows 实际程序保存、关闭进程和重启读取通过，开发安装包已交付。作品、账号和队列继续使用界面明确标识的模拟数据，原生设置及书单保存是真实的应用数据文件操作。本批没有进行真实账号操作、漫画下载、漫画入库或生产启用。

## 本批交付功能

| 模块 | 本批实现 | 使用方式或边界 |
| --- | --- | --- |
| Windows 桌面开发壳 | Tauri 2 主窗口、固定应用标识、独立 GUI 依赖锁、Windows 构建和打包流水线 | Windows x64 开发版，来源和队列仍是模拟数据 |
| 原生偏好保存 | 外观与资源设置写入应用数据目录，保存成功后才能显示成功反馈，重新打开可读取 | 原生故障不会回退到浏览器保存；资源设置尚未驱动真实调度器 |
| 自定义背景 | 原生系统选择器、PNG/JPEG/WebP 内容解码、大小和尺寸限制、缓存图片字节 | 原生上限 8 MiB，浏览器预览上限 2 MiB；保存后移动原图不影响缓存 |
| 混合来源书单 | 新建、改名、归档、恢复；同一作品可加入多个书单，支持单独移出 | 来源与作品 ID 一起确定身份；归档保留全部关联，移出不删除漫画 |
| 作品整理 | 从详情页或多选栏加入书单；支持当前筛选全部作品与离屏成员 | 已入库、排队、待复核作品也可整理，下载资格另外检查 |
| 页面上下文 | 保留选中书单及搜索/来源上下文，支持详情与设置往返、密度切换时恢复作品位置 | 刷新后保留书单文档；未承诺恢复每项临时界面状态 |
| 故障恢复 | 读写互斥、重复提交阻止、保存失败保留草稿、冲突后弹窗内重新读取再重试 | 不会自动覆盖其他进程的新版本；损坏或未来版本保留原文 |

原生背景名称会清理控制字符和路径分隔符，并按 Unicode 码点限制长度。既有浏览器背景数据保持兼容，不会仅因新文件名规则被悄悄改写。

书单暂时无法解析的作品引用会保留并显示在“资料暂不可用”区域；用户可以只移除该书单关联。书单名称最多 80 个字符，最多 100 份（含归档）、每份最多 2,000 个成员，全部书单合计最多 20,000 个成员，重复添加同一来源和 ID 不会扩大计数。

## 原生数据与权限

Windows 文件位置为：

```text
%APPDATA%\com.mangamonitor.workbench.preview\workbench-preview-v1\preferences.json
%APPDATA%\com.mangamonitor.workbench.preview\workbench-preview-v1\booklists.json
```

两个文档分别带有 schema 版本和递增 revision。保存先取得进程内互斥锁和跨进程文件锁，再读取并校验磁盘版本，写入并同步临时文件，最后替换目标。不能读取原文件、版本冲突、未来格式或路径重定向时会拒绝写入。遗留临时文件不会被擅自当成正式数据恢复。

前端只获准调用主窗口的五项命令：读取/写入设置、读取/写入书单、选择背景。没有通用文件、命令执行或任意路径接口；远端页面和其他窗口不获这些权限。存储打开失败时窗口仍可显示错误及重新读取入口，文件操作和图片解码在后台工作线程完成。

这里的原子保存针对应用配置文档，不代表已完成真实漫画任务的中断恢复、库存授权或云端发布。
