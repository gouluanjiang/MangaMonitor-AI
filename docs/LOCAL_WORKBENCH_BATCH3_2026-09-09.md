# 第三批开发记录：真实账号与来源资料

日期：2026-09-09。分支：`codex/local-workbench-preview`，沿用草稿 PR #19。Windows 开发版版本：0.3.0。

当前状态：实现已进入验证。此记录不代表真实账号已经验收；尚未接收或使用用户凭据。CI 状态及安装包证据会在验证后补齐。

## 功能与边界

| 功能 | 本批实现 | 验收边界 |
| --- | --- | --- |
| 两源登录 | 设置中分别连接 JM / 哔咔，验证返回的账号资料后显示连接成功，支持退出和重新登录 | 密码只用于本次登录；真实网络行为仍需用户账号验证 |
| 保留登录 | 可选择把服务端会话存入 Windows 凭据管理器；下次启动重新验证会话 | 密码不落盘；系统存储失败不回退明文；失效记录保留供重试 |
| 切换账号 | 会话代际隔离，旧响应丢弃；凭据比较与修改受跨实例互斥锁保护 | 冲突提示重新读取，旧实例退出不会删除新实例会话 |
| 在线收藏 | JM 收藏文件夹、JM/Pica 分页收藏与显式刷新 | 每次用户操作最多请求一页，不自动完整扫描 |
| 发现与详情 | 关键词搜索、作品 ID 或受支持链接解析、单作品详情、受限封面 | 原链接仅提取 ID，不让前端指定请求域名；真实库存与下载状态保持未接入 |
| 收藏操作 | 从作品详情收藏/取消收藏，先读取、最多提交一次切换、再读取核实 | 响应不明时保持未确认，重新核实前禁止重复提交；尚未操作真实收藏 |
| 本机关注 | 关注作品与作者名称、取消关注，按来源及远端账号隔离保存 | 本机关注可手动查看作品/按作者名称搜索；没有伪装成网站关注或自动监控 |
| 真实作品书单 | 真实详情/多选加入既有书单，两源引用同时存在；已读资料可回到详情 | 书单仅保存来源和 ID；缺失资料关联保留，一次显式读取最多 20 部 |
| 内存与错误处理 | 元数据、页数、封面解码与并发有界，断网/限流/403/过期分别保留状态 | 缺失页数、章节数和分页末尾证据仍为未知，不填 0 或宣称完成 |

已有本地漫画库和队列仍是明确标注的演示数据；设置、书单和本机关注保存是真实本机文件操作。新账号来源页使用独立 DTO，不能将真实作品加入演示下载任务。

## 存储与权限

- Windows 会话槽位：当前 Windows 用户的 `MangaMonitor/WorkbenchPreview/v1/Accounts/{JM|Pica}`，不枚举其他凭据。
- 本机关注：应用数据目录下 `workbench-preview-v1/following.json`，沿用版本、CAS、跨进程锁和原子替换；损坏/未来版本保留，拒绝覆盖。
- 关注账号键为来源与远端账号 ID 的散列。文档不是加密数据库；具有当前用户文件访问权限的程序可以读取本机关联。
- 主窗口增加八条专用 `source_*` 命令。原生客户端控制固定 API/CDN、请求预算、会话和文件位置，前端没有通用网络、路径或进程接口。
- 登录会话和密码不会写入书单、关注、日志、报告、仓库或 CI 工件。CI 使用合成凭据，真实来源请求被禁止。

## 验证分层

1. 合成协议用例：登录/恢复、分页、签名/解密、详情身份、单次收藏切换与结果核实、封面与数据边界。
2. 账号服务与本机存储：失效/切号、外部凭据更新、跨实例 CAS、关注隔离与冲突、旧封面响应拒绝。
3. Windows 凭据管理器：仅在临时 CI 用户中写随机专用测试槽位，验证读回、更新/删除、跨进程互斥与冲突；清理仅测试自身槽位。
4. 前端 Node 与 Chromium：原生 IPC 模拟覆盖两源切换、旧响应、登录错误、书单与关注冲突；这些不是实际账号验证。
5. Windows 实际 WebView：构建后的真实窗口、IPC 拒绝合成登录、密码清空、原生文档保存和重启读取。
6. 用户真实账号：待开发包通过以上检查后，在本机应用中输入；先登录、读取少量收藏/搜索/详情，再由用户在界面选择要验证的收藏操作。

本批没有进行本地重编译或全量测试。完整编译、跨平台测试、Clippy、WebView 与打包交给 GitHub Actions；本机仅做格式与依赖锁等轻量检查。
