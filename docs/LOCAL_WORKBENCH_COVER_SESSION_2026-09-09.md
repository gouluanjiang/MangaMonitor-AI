# 运行期间封面保留与 JM 封面修复报告

日期：2026-09-09。Windows 开发版：**0.3.2**。本批实现、自动验证、构建页面检查、安装包校验及用户真实应用验收全部完成。用户于 2026-09-09 明确确认本批功能和原列三项复测均通过，未发现问题。

## 最终方案

按用户最新要求，封面仅保留在本次应用运行的内存中。成功加载后，上下滚动、卡片卸载、详情返回和设置页往返均复用；关闭程序后释放，下次启动重新读取。原生封面命令不读写图片缓存文件。收藏元数据与读取进度仍独立保存，关注、书单和登录会话的持久化继续有效。

连续浏览仍采用接近底部时自动读取下一批，哔咔每批沿用来源的 20 本。无需一次加载 1876 本，也无需反复点击下一页。本批没有修改已确认正常的 JM 正倒序。

## 完成的功能与关键改动

| 功能 | 结果 |
| --- | --- |
| 本次运行封面保留 | 按来源、登录会话和作品隔离，合并重复请求；离屏保留成功图片，退出账号或切换账号释放旧图片，拒绝旧会话迟到结果。 |
| 内存与请求控制 | 最多保留 4096 张、256 MiB 压缩图片及估算元数据；同时请求最多 2 个。使用 Blob 和可释放的对象 URL，虚拟列表继续只绘制附近卡片。 |
| 失败重试 | 固定区分超时、访问受限、限流、地址不存在、服务端响应和图片校验异常；重试只清失败状态，成功封面继续复用。失败不使账号过期，也不证明作品被删除。 |
| JM 封面兼容 | 按项目固定上游源码增加两处固定移动 CDN 候选，保留旧候选；单次 10 秒、整体 30 秒，跳转与回退共享最多 4 次 GET。仅连接、超时、404、502–504 可回退，封面请求不带账号凭据。 |
| 旧磁盘封面清理 | 只处理合法旧索引登记的固定图片槽位和旧临时文件；不遍历、不递归。清理在首次文档存储初始化锁内执行，再开放设置/书单读取，避免启动争锁；失败不阻断打开。 |

旧缓存路径不安全、索引损坏或无法确认归属时保留文件，不猜测删除。收藏元数据、设置、关注、书单和凭据不属于封面清理对象。仍在磁盘上的元数据不包含封面图片内容。
