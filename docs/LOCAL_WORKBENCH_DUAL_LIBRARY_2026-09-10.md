# 双库记录与现有下载目录接入

## 本批范围

本批实现手机入库名单、电脑下载目录与在线作品之间的核对。手机有记录即显示“已入库”；仅电脑存在则显示“已下载”。电脑副本在传入手机后继续保留。

- 手机名单：原生选择 TXT，支持 UTF-8 和带 BOM 的 UTF-16；更新导入快照并保留手动标记，支持撤销单条手动标记。仅保存名单和来源引用，不连接手机。
- 电脑文件：原生选择目录，增量读取一级作品文件夹及现有 ZIP/CBZ；RAR 保留条目并提示格式限制。读取 JM/Pica 下载器元数据、标题、作者、标签、实际图片文件数及按需封面。
- 浏览：电脑与手机分栏、搜索、排序、5/7/9 密度、虚拟列表、详情返回位置和当前运行期封面缓存。重启恢复私有索引，不自动扫描全部文件。
- 核对：来源编号或手动关联提供准确引用；单纯相似标题只提示候选。手机 TXT 与电脑完整文件名去一个压缩后缀后按 Unicode NFC 精确核对，保留作者、版本和翻译等名称限定。明确来源的手机标记不会传播到同名其他来源。
- 边界：手机首次读取失败显示待核对；TXT 解析失败、修订冲突保留原记录。临时下载章节不计入正文，只有封面的作品单独提示。所有媒体只读，不下载、移动、删除或改写现有文件。

## 与用户现有库的核对

用户指定的手机 TXT 有 2833 条不重复原文件名；电脑根目录有 586 个作品文件夹。名称对比确认 487 个电脑目录在手机名单中有完整同名记录，99 个暂未匹配手机名单。该结果仅依据名字，不声称验证了每本内容完整性；实际名单和逐本结果仅保留在用户本机，未进入仓库或 CI。

对三个电脑作品目录进行了只读结构抽样：均有顶层封面与 `元数据.json`，以及包含图片和章节 JSON 的子目录。已对照上游 pinned 源码确认 JM/Pica 数据形状。Pica 安装程序被核对存在，但本批未扫描任何未获指定的 Pica 媒体目录。

## 验证计划与状态

候选由主 Agent 复核，独立 QA 覆盖状态优先级、同名不同来源、名单更新、持久化、取消/暂停/错误、封面缓存与虚拟列表。原生合成文件测试覆盖只读目录/压缩包、私有文档原子保存、手机标记不删除电脑副本、来源引用与限额。Windows 实际 WebView smoke 扩展手机记录重启和原生库空状态。

正式验证仅在 GitHub Actions：UI 格式/Node/类型构建/Chromium，Windows storage/library/IPC/Clippy/实际 WebView 与重启，Linux workspace/Clippy 和既有 Windows core 回归。此提交记录实现和待执行验证；以该提交对应的 CI 结果与本机最终开发报告记录实际通过情况。没有本地编译或重复测试。

## 未完成与交付

本批不接入真实下载队列、不传输手机文件、不修改生产库存。未来 JM/Pica 下载结果采用用户现有下载器的作品/章节目录格式，详见 [兼容记录](UPSTREAM_DIRECTORY_COMPATIBILITY_2026-09-10.md)。PDF/CBZ 导出已取消；应用内更新继续冻结到正式 V1 之后。

应用版本保持 0.3.4，不单独生成 0.3.5 安装包；本批与已通过 CI 的 Pica 连续目录修复一起等待后续较大交付。真实界面与双库名单验收待该交付进行，不能记为用户已验收。

已知范围：RAR 不解析封面；ZIP64、分卷、加密及非 stored/deflate ZIP 暂不支持。目录中的图片计数不等于逐图内容校验。只有文件名而缺少来源编号的手机记录，无法自动确定所有在线作品的身份，可通过明确来源的手动标记补充。封面缓存有容量上限，关闭程序释放，不写本地封面缓存。
