# 收藏浏览与封面修复批次报告

日期：2026-09-09。Windows 开发版：**0.3.1**。本批开发、自动验证、实际构建页面检查及安装包校验已完成；修复后的真实账号验收单独列在文末。

## 采用的方案与难度

实现难度为中等，主要工作是分页状态、封面兼容和大列表显示。1876 本的元数据可以处理；一次进入页面就请求所有分页，会增加等待和无用请求。因此按用户最新选择，采用**滚动接近底部时，自动加载下一个来源分页**。哔咔沿用每页 20 本，用户无需反复点“加载下一页”，也不必等待全量读取后再浏览。

## 本批完成的功能

| 功能 | 交付行为 |
| --- | --- |
| 连续浏览收藏 | 首次读取一页，接近底部自动续读；停留在已读区域时不继续拉完整收藏。提供进度、暂停、继续和失败重试。收藏页取消手动“下一页”，搜索仍独立分页。 |
| 哔咔正反序 | 使用来源自带的收藏时间“从新到旧 / 从旧到新”；两种方向都直接从相应一端读首批，再随滚动续读。 |
| JM 倒序 | 保留已确认正确的默认收藏时间顺序。主动选择全局倒序时准备完整索引后反转，可暂停；准备完成后显示倒序开头。 |
| 本机收藏缓存 | 按来源、已验证账号、收藏夹和方向隔离，保留读取进度及上次完整结果；重新进入时核对首页，变化时重建当前结果。磁盘缓存不可用时仍可在线浏览。 |
| 封面修复 | 补齐哔咔受限存储域名、变换路径及有限跳转兼容；修复旧作品封面描述缓存淘汰后的恢复。只加载视口附近封面，最多同时请求 2 个，提供重试及有界本机缓存。 |
| 大列表显示 | 5/7/9 列按可见行绘制，选择仍覆盖全部已读数据。保留密度、详情往返的作品锚点；用户主动滚动优先；修复大列表末尾缩窗白屏。 |

网站收藏写入保留逐项确认与读回核验。封面请求不带账号凭据；缓存不授予收藏写入或下载权限。没有接入真实漫画库存、正文下载或入库，生产开关保持关闭。

## 已验收与仍需复测

用户已确认通过：两个来源登录、收藏读取与刷新、原有来源顺序、标题和作者、关注与书单重启持久化、记住会话。JM 原排序异常判断已撤回，本批没有按该判断修改默认来源顺序。

安装 0.3.1 后重点复测：

1. 收藏列表和详情页封面是否出现；之前失败的封面可点“重试封面”。
2. 哔咔列表连续滚动是否按批增加，暂停/继续是否符合预期。
3. “收藏时间：从旧到新”是否直接显示最早收藏的一端。
4. 在自己选定的一部作品上验证收藏或取消收藏，再刷新网站核对。该项本批尚未真实操作。

来源在分页期间发生增删时，应用会保留已读数据并要求刷新，不把变化中的结果报告为完整。JM 首次全局倒序需要完整索引；哔咔原生反序无此等待。索引上限为 20,000 条与 32 MiB；所有账号磁盘缓存预约总额最多 256 MiB，另有至多 32 MiB 原子临时写入和 64 KiB 索引开销。1876 条合成分页及 2000 条缓存场景已覆盖，真实响应速度取决于来源和网络。

真实库存、持久下载队列、漫画文件入库及生产验收仍属于后续开发批次。
