# JM 空白元数据兼容修复报告

日期：2026-09-09。Windows 开发版：**0.3.3**。实现、代码审查、云端验证、安装包校验和用户真实应用验收均完成。用户明确反馈本次修复已验收通过。

## 结论与定位依据

这是项目对 JM 可选元数据的兼容问题。用户反馈的两本在公开详情接口均返回 HTTP 200、业务码 200，作品编号吻合；标签数组分别有 7 项和 6 项，其中各有一个空字符串。标题、作者、页数等解析所需字段满足既有校验。用户也确认网页可读取两本的图片和详情，没有依据将这两例归为网站内容不可用。

应用原来接受可选字段的空字符串形式，却拒绝数组内的空字符串，使整条详情解析失败。详情失败时无法登记封面描述，列表滚动后恢复已淘汰的封面描述也依赖详情读取，因此连带封面失败。“重新读取当前作品”再次遇到相同空标签，仍然报错。

本机仅对用户提供的两本作了两次不带账号凭据的公开详情请求，只保存字段类型和长度摘要，没有保存原始作品内容。没有遍历全部收藏，没有请求漫画图片或正文。不能推断所有收藏只有两个异常；修复适用于全部同类数据。

固定上游的 [JM 详情响应定义](https://github.com/lanyeeee/jmcomic-downloader/blob/f0cdd724af6892002f2fb7be883b88832cebe7e9/src-tauri/src/responses/get_comic_resp_data.rs) 将作者和标签表示为字符串数组，没有逐项非空要求。项目既有来源和协议版本不变。

## 完成的改动

- JM 可选作者、标签数组中的空串及纯空白占位被忽略；有效项保留原内容、顺序与重复项。
- 过滤前仍检查原始数组最多 64 项、每项必须为字符串且最多 2000 个 UTF-16 单元，不能用空项绕过资源限制。
- 必需编号、标题、收藏状态、页数、整条作品大小和 Pica 的规则继续按原标准校验。
- 新增 5 项合成回归，并扩展已有封面描述恢复测试：详情成功登记封面；描述淘汰后只读一次详情即可恢复，后续封面访问不反复读取详情。
- 不按真实作品编号写例外；真实反馈编号、账号、原始作品内容未进入仓库或测试夹具。
