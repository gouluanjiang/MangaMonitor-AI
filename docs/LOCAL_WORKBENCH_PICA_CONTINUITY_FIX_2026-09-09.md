# 哔咔连续读取修复报告 · 待下次集中发布

日期：2026-09-10（延续 9 月 9 日诊断）。用户要求本次不单独生成安装包，修复随下一次较大进展集中发布。版本号保持 0.3.4，独立 0.3.5 安装包取消。当前实现审查和 CI 待完成，真实完整目录验收留到新安装包发布后。

## 完成的需求与关键改动

用户选择按 JM 方式统一：Pica 始终读取同一份从新到旧目录，显式切换收藏时间方向或选择从旧到新时自动继续读完整，再在本机翻转显示；之后切换方向复用这份完整目录。普通进入收藏页继续按浏览位置分批读取，输入搜索本身不启动全读。

查明的两个停止原因均有真实只读响应证据：来源返回 HTTP/API 200，但旧到新第 33 页含完全相同的重复记录，新到旧第 28 页含负整数 pagesCount。Pica 返回了异常元数据，应用原校验又把整页阻断，因此属于应由本项目处理的兼容性问题，并非证据表明账号被封禁或读取次数耗尽。

- 负整数 Pica 页数保留为“未知”；不把它编造成 0 或取绝对值。章节数、其他错误类型及 JM 校验保持原规则。
- 同一页完全相同的 Pica 收藏记录允许继续读取，按来源条目计进度；列表、搜索与选择按不同作品去重，并明确显示重复条目数。冲突记录、跨页重叠和搜索重复仍会停止。
- 元数据快照保存分页边界，使重启恢复时仍能验证重复仅发生在同页。旧版无重复完整缓存可复用；旧版 Pica 无边界的部分缓存首屏核对后重建一次，避免猜测旧分页边界。
- 读取失败明确显示“读取已停止”，保留进度并提供重试；不再误显示“向下滚动继续读取”。设置往返或切换方向不会偷偷重试。标题排序取消全读后，重试只补读失败页。
- 暂停/继续沿用单个顺序读取器；250 毫秒既有页间隔、现有请求/内存上限和虚拟列表保留。封面仍仅本次程序运行内保留，不写入磁盘。

## 执行分工与验证

主 Agent 负责根因复核、协议/读取器改动、最终源码审查、提交和交付。独立 Agent 分别承担 UI 候选和核心只读审查；缓存边界审查问题修复后由主 Agent 再复核。所有正式测试、格式检查、类型检查、构建及桌面重启测试都只在 GitHub Actions 运行，本地不重复跑这些任务。

本地诊断共 4 次只读 Pica 元数据 GET（两页各两次），使用当前已记住会话，只保存脱敏形状/计数。未把凭据、账号、标题、作品编号、原始响应或漫画数据保存进仓库；没有读取图片、改网站收藏或下载漫画。

回归覆盖 1877 条收藏记录的 94 页完整读取、同页重复、未知页数、末页搜索、不同作品选择、双向复用、停止后手动重试以及缓存边界。最终 CI 数量和提交证据将在验证后补充。普通 CI 仍构建并测试实际桌面程序，但不生成/上传 NSIS 安装包；以后明确准备交付时使用手动 workflow_dispatch 的 package_installer 开关。

## 已知限制与未完成事项

完整目录是某次读取的快照；核对首页不证明全部远端记录始终未变化。新出现的冲突/跨页重叠、来源限流或网络异常仍会明确停止，需要重试或刷新。未执行真实 5000～10000 本压测，也未对用户收藏做完整扫描。本次 1877 条合成样本中的重复数量只是测试数据，不是用户真实全部收藏的去重统计。

待下一次集中发布、用户安装后验收：Pica 切换一次倒序，无需滚动便读完来源报告总数；完成后双向切换不清空已读目录；搜索先前中段或末段的作品/作者。既有 JM 和封面已验收项不要求重做。

用户已确认保留四项最小可靠性：错误可见并可手动重试、未完成不得标完成、保留完成 ZIP 避免重复下载覆盖、正常退出保存队列/完成状态。PDF/CBZ 导出取消，后续新作品以 ZIP 入库；复杂离线/长时自动重连不扩张为新必做项。程序内更新仍冻结至正式 V1 之后。真实库存、下载/入库仍是后续开发阶段；PR #19 保持草稿，生产保持关闭。
