# B 批：电脑漫画库与 JM / Pica ZIP 下载

本批把电脑目录中的实际作品文件作为入库依据，新下载按一本一个 ZIP 保存。文件名沿用已确认的社团／作者、标题、语言与版本命名，去掉生成的来源编号和开头 C 展会前缀；完整来源标题、编号、章节与元数据留在 ZIP 内。

## 行为

- 漫画库、在线作品状态与作者补全均使用电脑文件；手机 TXT、手机标记和分类书单退出界面与启动读取。旧私人文档保留为兼容数据，不再决定已入库。
- 新 JM / Pica 下载共用 ZIP 容器和外部命名。JM 保持已验收的 20 图并行处理、JPG / GIF 输出，Pica 保留来源图片格式。使用 Stored ZIP，不再压缩已经压缩的图片。
- 下载中保留已验证的临时图片以便继续；完成 ZIP 校验和漫画库登记后清理当前任务的临时图片。封面仍仅在应用会话内缓存，没有新增磁盘封面缓存。
- 旧目录任务按原审批与收据继续；新 ZIP 使用独立输出配置绑定。既有文件不覆盖，文件缺失后需重新准备与确认下载。无法读取、内容变更或资料冲突不作为缺失。
- 设置的“漫画库”页可导入 A 批 JSON 路径映射。逐个核对目标 ZIP 的 SHA-256、格式与文件身份，一次保存私人索引映射，然后重新读取目录。保留原关联、下载历史和版本／语言关联；不改写历史下载收据，不移动或删除漫画。
- 作者补全的基础库存判断同步迁移：电脑中存在已确认汉化即补齐，仅日文则等待／发现汉化，未知版本或损坏文件继续核对。完整版本复核体验与真实双来源验收仍属于 C 批。

## 下载闸门复核

这是 `DOWNLOAD_EXECUTOR_THAW_GATE.md` 要求的本批受影响行为复核。沿用 `upstream-source-reference.md` 已记录的 JM `f0cdd724af6892002f2fb7be883b88832cebe7e9`、Pica `77c8b62ede42b3afc074506d092313816af8092d` 与 Python 参考 `9fddb0494caf0cdc812ac6cbfc1c62f4f845b058`；请求、认证、分页、解图、重定向规则与许可证材料未变。

新增权限仅改变显式确认下载的最终容器和电脑私人索引投影。容器类型进入目标绑定；旧序列化记录缺省保持目录配置。ZIP 包装读取已验证的既有布局，先生成临时包及文件证明，再独占创建已批准根目录内的最终 ZIP，恢复只接受当前任务记录的文件身份与相同字节前缀。最终全包哈希、内部清单和各文件哈希核对后才能登记完成；索引失败可用同一收据重试。进程退出不会凭历史记录启动下载。

迁移映射只是当前文件位置的证据，不授予执行、替换或删除权限。旧路径必须确实不存在，目标 ZIP 必须匹配对应表哈希；同名现存原件、来源冲突、根目录变化或并行队列变更使导入失败，私人索引保持原样。映射覆盖变动项而非整个目录，之后仍需普通目录读取。路径、漫画条目、账号与映射内容仅在用户本机，仓库和 CI 仅使用合成样本。

保留 `production_enabled=false`，PR #19 保持草稿未合并。真实媒体仅本机经用户选择执行；CI 不接入真实来源。版本维持 0.3.4 Dev，本批不制作安装包。
