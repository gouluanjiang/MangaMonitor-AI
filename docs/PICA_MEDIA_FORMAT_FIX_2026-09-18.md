# Pica 下载图片格式兼容修复

## 问题与范围

V1 最终体验已于 2026-09-17 验收通过。本次是用户明确要求修复的下载维护项，后续扩展仍待讨论。

只读诊断在失败任务的下一章首张确认：路径为 `.jpg`、HTTP 类型为 `image/jpeg`，正文却是完整可解码的 WebP。旧代码根据后缀强制使用 JPEG 解码器，触发 `DOWNLOAD_MEDIA_IMAGE_INVALID`。已有暂存图片的数量、字节数和哈希一致。旧任务未保留原始失败响应，因此不将当前响应断言为历史失败字节的逐字复现。私人编号、标题、地址、原始目录和会话均留在 Git 外。

## 修复

- Pica 按图片正文识别 JPEG、PNG、WebP、GIF，使用原有尺寸和内存上限完成解码验证；不接纳 HTML、损坏或不支持的图片。
- 原始字节不变，避免再次压缩或丢失动画；落盘扩展名随真实格式调整，正常 `.jpeg` 仍保留 `.jpeg`。
- 原请求 URL、媒体编号、目录描述和描述哈希不变。续传记录和完成清单使用真实扩展名，目录与 ZIP 输出沿用验证后的清单，已有正确图片可继续使用。
- 续传只允许同章节、同序号、同文件名主干及受支持的扩展名；保留哈希、文件身份、未登记文件拒绝、写入前进度和授权检查，并核对完整文件的格式签名。部分写入继续按原进度规则校验。
- JM 解扰／JPG 输出仍严格验证。后台已验证结果同时绑定来源和原描述，不能跨来源使用。

没有增加请求、重试、域名、自动下载、覆盖或删除行为；生产开关、同来源所有权和发布状态不变。
