# Pica 单本下载批次

## 范围与验收状态

用户已验收 JM 单本下载、显著提速和删除后重新下载，并要求继续下一批。本批接入 Pica 单本桌面下载：从收藏/详情或手工 ID 预备作品，确认电脑目录，完整取得章节和图片，保存兼容目录，再登记电脑“已下载”。真实验收由用户自行选择作品并操作；不预先读取私人漫画、不替用户启动真实下载。

本文件记录实现范围和验证分配。源代码完成、对应提交 CI 通过、用户真实验收是三个独立状态。准确的 CI 提交/运行号、测试结果、Dev EXE 哈希和真实验收状态写入本次交付目录的报告及 PR #19。不得把本文件或合成数据当作真实来源已验收。

## 完成的功能

- 下载入口支持 JM / Pica；作品确认、来源编号、当前登录账号和选定电脑目录保持一致。JM/Pica 共用队列，一次运行一本。
- Pica 复用现有图片并行管线，最多 20 个图片生命周期；元数据采用下载场景的即时节奏。普通监控客户端继续使用原有节奏。
- 收齐 Pica 章节分页后按章节顺序整理；章节和图片分页核对页码、分页总数及记录总数，缺页/重复/数据变动不会产生完整作品证明。
- 当前 Pica 会话仅在原生进程内交给下载器。登录替换或退出使旧会话失效；媒体请求不携带登录令牌，队列、文件元数据和前端响应不保存令牌。
- 兼容目录包含作品元数据、根封面、章节元数据和三位页码图片。Pica 漫画页保留来源 JPG/JPEG、PNG、WEBP、GIF 格式；JM 新任务继续 JPG，历史 WEBP 任务仍可读取。
- 全部文件完成、核验并登记电脑索引后才显示“已下载”；手机名单保持独立。传入手机后手动标记或导入最新 TXT，电脑文件继续保留。
- 复用暂停、继续、手动重试与正常重开队列恢复；重新打开应用不会自行启动未完成下载。缺失/文件变化/保存根不可访问继续分别显示，完整目录被删除后可显式新建下载任务。

## 实现与兼容边界

历史下载记录未保存来源时按 JM 读取，原 JM 批准绑定保持不变；Pica 使用独立来源和布局绑定。执行、最终清单、收据、电脑登记及重新下载去重均使用来源与作品 ID。内部沿用既有 `jm_download_*` IPC 名称以保持兼容，其参数现在支持两种来源；用户界面显示正确来源。

目录中的来源元数据仅含可安全保存的作品信息；上游格式所需而当前浏览接口未提供的字段使用兼容默认值，不作为来源真实信息或完成证据。根封面复用现有从已验证首张页面生成的 JPG 缩略图，不另加来源封面网络请求。此文件属于用户下载作品；在线浏览封面仍只保留在当前会话内。

## 验证分配

本地执行：源代码检查、格式整理、固定上游对照、工件下载与哈希核验。合成测试、类型检查、浏览器测试、Rust/Clippy、Windows 构建和桌面烟雾验证全部交给 CI，同一提交同一套测试不在本地再跑。

重点覆盖：Pica 章节排序和完整分页、源会话失效、跨来源控制拒绝、混合图片格式、目录定向登记、缺页不完成、手机名单不变、旧 JM 记录、重新下载和前端来源切换。测试仅使用合成元数据/图片/临时目录，CI 不访问真实漫画或账号。

## 真实验收

CI 通过后交付 Dev EXE。用户登录 Pica，选择电脑保存目录，再自行选择手机和电脑都未有的一本；可从作品详情下载，也可在下载页切换 Pica 后填 ID。确认页检查作品和最终目录，再点击确认。

观察队列进度，完成后检查章节、图片顺序、实际原图格式与“已下载”。多章样本可顺带验证章节顺序；随后正常关闭并重开，确认队列和电脑状态保留。手机状态应维持原样。无需重新验证已经通过的 JM 性能和重新下载修复。Pica 真实耗时和特殊来源数据仍以用户反馈为准。

版本暂保留 0.3.4，以文件名/提交哈希区分 Dev 交付；安装包留待计划版本。应用内更新仍冻结至正式 V1 后讨论，不做 PDF/CBZ 导出。
