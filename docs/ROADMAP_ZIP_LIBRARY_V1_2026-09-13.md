## A：存量漫画库统一 ZIP

2026-09-13 进展：A1 五本样例已验收；A2 首批 937 个 ZIP 已核对，后续 138 项例外处理成功，正式库现在全部是 ZIP。原 908 个对象经最新明确授权、替代内容复核后已删除，释放约 17.13 GB；另 64 份例外原件约 1.08 GB 已保留在库外备份。剩余 12 个作者待补和 4 个含 7 张原有空图片的 ZIP 保持不变，不以猜测补信息或内容。合并路径表 1,075 条、1,073 个 ZIP 目标已准备，应用索引尚未迁移。私人路径及详细条目仅在本机报告。

下面的 A 步骤已完成文件整理和异常登记，保留作为执行依据；下一批推进 B，16 项问题独立保留。

1. 复用迁移清单明确作品／合集／章节边界，社团总目录不能整体当一本。
2. 先做代表性样例并验收，再批量转换 RAR 和图片作品目录。正常 ZIP 尽量保留，不重新编码原图，保留 JPG/WebP/GIF 及元数据。
3. 沿用社团、作者、标题及版本／语言／卷次信息，字段不足保留可靠原名，不猜造作者或来源编号。
4. 生成旧路径到新 ZIP 的对应表，供索引、来源关联和下载记录迁移。
5. 核对图片内容、数量、章节与元数据；结果确认后再按明确安排退出旧格式，不保留两套完整正式副本作为长期方案。

完成标准：正式 ZIP 可验证、关联可追溯、异常有独立清单。RAR 只用于迁移输入，不另建长期 RAR 阅读器。统一 ZIP 不会补出旧档案缺少的来源 ID，标题／作者匹配及人工复核仍需保留。机器运行时间由样例测算，不套用 USB 速度。

## B：电脑漫画库与统一新下载输出

1. 库、收藏、详情、队列和下载准备统一查询电脑实际文件；经校验并登记的新 ZIP 即已入库，文件缺失后仍可按已验收逻辑重新准备下载。
2. 退出手机名单和手机标记，取消分类书单入口、按钮和设置；保留必要关联迁移依据，不改动手机漫画。
3. JM/Pica 共用外部命名与 ZIP 输出：`[社团名 (作者名)] 作品标题 [语言或版本标签].zip`，按真实字段降级；原始来源标题与元数据保留。
4. 下载过程使用临时图片，正式库输出为一个 ZIP；保留已验收速度、队列操作与重下能力。
5. 接入 A 批合并路径表（1,075 条、1,073 个 ZIP 目标）。原 908 对象现已删除，另外的改名／库外备份路径也需迁移，不能继续依赖旧原件存在。保留已有来源证据，未知关联继续复核；真实 ZIP/CBZ 样本补必要兼容，不扩展为阅读器。

完成标准：新旧状态一致、重启关联保持、两源各通过一次真实 ZIP 入库；旧双库与分类书单退出日常流程。

## C：版本关系与作者作品补全

1. 复用已有人工配对、语言版本族，补齐同作同版本／同作不同版本／不同作品复核及否定匹配保存。
2. 同版本默认复用一份，可明确换源或另存；不把不同版本合并为同一库存事实。
3. 适配已有作者补全页面，每个关注作者同时检查 JM/Pica；保留新旧遗漏，不按最后扫描或入库日期截断。
4. 电脑存在确认对应的汉化即补齐，仅日文则等汉化。显式检查中按已确认选项下载汉化新副本，普通缺失由用户选择。
5. 验收真实作者、跨来源版本、汉化新增、停止和结果保留，再按实际名单验证规模。

完成标准：已汉化不误报缺失或重复下载，入库准确改变遗漏列表；旧日文不被隐式覆盖或删除。

## D：JM 每周必看与 Pica 排行榜

1. 两个独立入口接真实列表，保留各自来源顺序。
2. Pica 周排行等周期和筛选按来源实际能力核对，不照搬 JM 或构造混合排名。
3. 接封面、详情、库／队列状态、多选与下载，复用已有选书链路。
4. 两源各通过真实浏览和选书验收。

完成标准：来源数据和筛选可核对，并能进入统一下载入库链；设计稿、搜索页、周报摘要不能代替。此批属于原 F12，不是新增增强。

## E：自动发现与完整范围批量补齐

1. 接入应用运行期间新增收藏发现和作品关注检查，复用现有分页、缓存与进度，不强制每次打开都重扫全部作者和封面。
2. 汇总收藏新增、作者发现和作品需处理信息，保留原因、旧遗漏及未完成范围。
3. 对当前收藏夹／全部收藏准备完整计划，排除已入库、排队和待复核作品，一次确认后内部逐批调度。
4. 复用每批 50 本的执行能力，补跨批计划；全选不能只代表当前已读的一小段。
5. 保留暂停、失败隔离、正常关闭状态及明确继续；重试不重复下载已完成作品。

完成标准：不用手动翻完几千本再反复确认，完整范围、缺失数量与未处理原因明确。自动发现不取得全部作品的自动下载授权。

## F：原云端状态闭环

原云端发现到本地完成再返回状态的目标未取消。桌面私有队列与原监控状态需明确衔接，不能用桌面验收替代云端整链验收。

1. 复核已实现的扫描、审批、入库、任务完成模块，复用成果并明确真实验收缺口。
2. 落实原 Issue #7 的库存／完成状态发布，结合电脑主库重核边界；漫画、账号与私人完整库留本机，只处理原契约允许的必要状态。
3. 证明后续扫描不重复产生已入库作品的下载；本地入库与云端待同步分开表达，补同步不重新下载。
4. 完成保留架构的最终运行验收，不扩建已取消的复杂离线编排，不自动开启生产。

不重启作者批次已放弃的旧云端结果导入方案。若用户未来移除云端产品目标，应明确修改范围；当前不能默认为可跳过的增强。

## G：既定界面设置与正式 V1

1. 补齐真实电脑库最近入库区域、详情章节目录和必要文件信息；这不是阅读器。
2. 接原定资源配置、基础网络／错误阶段诊断，保留已验收的快默认值；不恢复图像处理和 ZIP 打包独立调节项。
3. 明确两源收藏写入验收，走通收藏／排行／关注发现、复核、批量确认、ZIP 入库、关闭重开。
4. 收尾实际缺陷、旧双库和书单文案，整理说明、版本与交接。
5. 按既有本地／CI 分工完成必要检查、正式 V1 安装包及旧数据兼容验收；生产启用仍保留独立的最终用户决定。

完成标准：保留的 V1 范围逐项有实现与验收依据，取消项退出待办，冻结项另列；不只凭构建通过宣布完成。

## V1 后与取消项

- 明确冻结至 V1 后再讨论：阅读器、应用内更新。
- 历史暂缓、没有重启排期：资料备份恢复、JM 远端收藏夹完整管理、托盘／自启、独立 TXT 编号文件导入等，详细分类见范围复核报告。多行编号／链接粘贴已经实现。
- 取消或退出：PDF/CBZ 导出、分类书单、手机入库名单；复杂离线自动重连不作为新必做项。
- 保留四项基本可靠性：错误可见可重试、不误报完成、不重复下载或覆盖、正常关闭后保存队列。
