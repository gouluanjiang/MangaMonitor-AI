# MangaMonitor V1 当前范围：手动检查作者更新与下载记录入库

2026-09-14 整理最新用户决定。用户已接受：只根据对应来源的下载记录和实际文件判断“已入库”，不再要求识别未登记的旧漫画或跨站同一本；完整分页保留，漫画关联和“不喜欢”全部取消。本文件是当前产品范围与接续顺序的依据；与旧路线、历史报告或旧事项冲突时，以本文件及后续用户决定为准。

**当前位置：用户已要求按路线继续开发，正在落实阶段 1–3。** 存量关联已取消。真实检查、下载和漫画库整理不在本轮代码开发范围；工程验证与用户真实验收分别记录。

## 用户要完成的流程

```text
打开 MangaMonitor
        ↓
点击“检查作者更新”
        ↓
检查关注作者在 JM 和 Pica 上的作品
        ↓
按对应来源的下载记录与实际文件，列出未入库记录
        ↓
用户选择作品并开始下载
        ↓
下载完整、ZIP 保存并核对成功
        ↓
保存该来源的下载完成记录，同一来源作品在各页面显示“已入库”
```

- 只有点击检查按钮才启动作者检查。打开程序本身不触发检查；不安排定时检查、后台周期检查或关闭软件后的持续监控。
- 检查同时覆盖 JM 与 Pica。复用已有来源读取、分页与检查进度，不从零重写已可用的来源代码。
- “作者更新”包含该来源尚未登记入库的新作和过去记录。再次检查不以最后扫描时间或最后入库日期清空它们；未登记的旧漫画即使电脑上已有，也可能继续出现，由用户自行跳过。
- 用户自行选择下载。取消旧的“发现汉化后自动下载”行为；检查按钮本身不授权下载任何作品。
- 保留上次检查结果、范围与时间，方便下次打开查看。保存结果不意味着软件关闭后仍在检查。
- 用户已确认：必须读完查询范围的所有分页才能给出最终统计；读取中显示进度与暂时数量，读取未完成或失败时说明未完成范围，不能宣称某作者所有作品都已入库。“所有作品”仅指本次两个来源能查询到的完整结果。
- 关闭软件后不继续检查或下载；保留必要记录与队列，下次由用户明确操作。

## 入库判断与统计边界

**按“来源 + 作品编号”的下载记录和实际文件判断入库。** 软件保留下载所需的来源编号、保存位置与完成记录；不再制作任何人工或自动漫画身份关联功能。下载失败、下载中或文件无法核实，不计作已入库。

| 情况 | 程序行为 |
| --- | --- |
| 通过软件下载作品 | 完整保存并核对后登记该来源的下载记录、本地文件与入库时间；同一来源作品在收藏、搜索、作者更新、排行同步状态，无需用户再扫描或手动入库。 |
| 同一来源、同一编号再次出现 | 复用下载记录并核对实际文件；已有有效下载记录可以继续使用，不重新下载来建立记录。 |
| 另一站出现同一本 | 不配对、不共享入库状态。JM 的下载记录不会让 Pica 的另一条记录自动已入库，反之亦然；用户自行选择是否跳过。 |
| 原有漫画没有对应的下载登记 | 库内文件仍可浏览，但不推断它对应哪条线上作品；在线结果可继续显示未入库，不再补做存量辅助关联或提供“这本我已有”。 |
| 已完成记录对应的文件被用户移除 | 保留必要文件存在性核对，避免只凭历史下载成功继续显示已入库；沿用已验收的重新下载流程。 |

**“未入库”表示该来源没有可核实的有效下载入库记录，不保证电脑上不存在同一本。** 用户已明确接受这个边界，并自行避免重复选书。页面应以简短范围说明表达统计口径，不恢复身份猜测、人工配对或人工补标。

两站结果按各自来源记录计数，不做跨站同本合并；同站同编号的重复返回可以合并。汇总与分来源数量必须使用同一口径。文件状态无法核实时保留待核实状态，不把读取失败算作文件不存在。

取消存量辅助关联的前置任务和人工关联入口。旧人工／自动关联不再作为此模型的入库依据，不得伪造成下载成功记录；实施时保留已有有效下载凭据和必要路径迁移证据，旧关系数据可作为不参与判定的兼容历史保留。本次不删除任何私人记录、账号或漫画文件。

| 功能 | 完成标准 |

| 统一漫画库状态与筛选 | 收藏、任意作者搜索、作者更新、排行、详情使用同一份对应来源下载记录和文件状态；可筛选已入库／未入库。漫画库保留入库时间排序和必要文件问题筛选，取消身份匹配待核对入口。 |
| 任意作者搜索统计 | 不要求先关注作者；读完本次全部分页后展示总数、已入库、未入库和筛选后显示数。仅当本次完整查询结果全部有有效入库记录时提示“本次查询结果已全部入库”，注明来源、范围与时间。 |
| 作者更新专页 | 侧栏有明确入口；点击检查，双来源读取，保留旧遗漏，用户选书下载，成功后更新列表与统计。 |
| JM 每周必看、Pica 排行 | 仍是 V1 必做。使用各来源实际榜单与可用筛选，接统一状态、详情和下载。 |
| 收藏、作品关注与批量选书 | 保留已有入口、完整范围读取、队列与多行编号／链接粘贴；补齐完整范围选书和内部批次调度，避免把“全选”仅解释为当前读到的一小页。历史发现待办不再引入常驻云端调度；检查沿用明确触发、手动选书的边界。 |
| 一本一个 ZIP 的电脑漫画库 | 保留统一命名、来源元数据和下载完成登记；保留已验收的两源下载、JM 速度和删除文件后重新下载行为。 |
| 基础可靠性与界面收尾 | 保留错误可见可手动重试、不误报完成、同站同编号的重复任务拦截、已有目标保护与正常关闭保存队列；收尾真实库详情、必要设置／诊断及页面操作一致性。不再承诺识别跨站或未登记旧漫画的重复。 |

未选中的作品继续留在结果里。“不喜欢”及其隐藏、数量、查看与撤销入口全部取消；不会以另一个名称重建忽略功能。

GitHub CI 仍可用于工程检查与构建。取消的是产品运行时云端监控／回传，不是开发阶段的 CI。已有历史代码和远端事项尚未因本次文档修改被删除、关闭或部署变更。
